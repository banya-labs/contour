## 2. Lenco Zambia Gateway Architecture & Webhook Flow

Contour uses **Lenco Zambia** ([`https://lenco.co/zm`](https://lenco.co/zm)) as its primary commercial payment gateway across Lusaka and the Copperbelt.

### The Checkout & Subscription Lifecycle:

```
┌──────────────┐         ┌───────────────────────────┐         ┌──────────────────────┐
│ Agency Admin │ ──────► │ Contour Billing Surface   │ ──────► │ Lenco API Collection │
│ (Grace)      │         │ (/dashboard/billing)      │         │ USSD Push / Checkout │
└──────────────┘         └───────────────────────────┘         └──────────┬───────────┘
                                                                          │ (MTN / Airtel / Card)
                                                                          ▼
┌───────────────────────────┐         ┌───────────────────────────┐   ┌──────────────────────┐
│ Organization Plan Updated │ ◄────── │ Webhook Verification      │ ◄─┤ Lenco Webhook        │
│ in PostgreSQL & Unlocked  │         │ (/api/webhooks/lenco)     │   │ transaction.success  │
└───────────────────────────┘         └───────────────────────────┘   └──────────────────────┘
```

### Technical Security Protocols:

1. **HMAC SHA-256 Signature Verification**:
   - Every incoming Lenco webhook payload is signed with the agency's shared secret key.
   - Contour verifies the `x-lenco-signature` header before executing database mutations:
     ```typescript
     const hash = crypto
       .createHmac("sha256", process.env.LENCO_WEBHOOK_SECRET!)
       .update(rawBody)
       .digest("hex");
     if (hash !== signature) {
       return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
     }
     ```

2. **Idempotent Webhook Processing & Status Re-query**:
   - Every webhook transaction reference (`data.reference`) is recorded in the `AuditLog` table.
   - As recommended in Lenco's official API documentation, Contour implements an active re-query verification service via `GET /v1/transactions-by-reference/:reference` to prevent spoofing and guarantee consistency during transient network outages.

3. **Dev / Demo Mode Bypass Protocol**:
   - When running in local development or interactive sales demos (`NEXT_PUBLIC_DEV_MODE="true"`), the billing surface provides an instant **"Upgrade to [Plan]"** flow that simulates immediate activation.
   - Allows sales reps to demonstrate plan upgrades and Pro features without initiating live mobile money debits.
