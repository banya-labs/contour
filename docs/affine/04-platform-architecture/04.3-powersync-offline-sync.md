# 04.3 — PowerSync Offline-First Field Sync (SQLite WASM)

> **Core Capability**: Zero-latency offline read and write execution on mobile devices, with automatic background synchronization upon network reconnection.  
> **Target Scenarios**: ZESCO power load-shedding, cell network drops in outer Lusaka subdivisions (New Kasama, Silverest, Chongwe, Leopards Hill).

---

## 1. The Offline-First Architecture

Standard web apps query the server over the internet for every page view and filter change. When an agent enters an area with no cell reception, the app hangs or displays a network error.

Contour flips this model by utilizing **PowerSync**:
1. PostgreSQL writes are streamed in real time via logical WAL replication to the PowerSync service.
2. The PowerSync service filters rows based on `sync_rules.yaml`.
3. The client PWA maintains a local **SQLite database** running directly inside the user's browser using WebAssembly (WASM).
4. All UI queries read and write directly against local SQLite with **0ms latency**.
5. When connectivity resumes, local mutations sync to the server in the background.

```
┌─────────────────────────────────┐
│     PostgreSQL 16 (Dokploy)     │
└────────────────┬────────────────┘
                 │ Logical WAL Stream
                 ▼
┌─────────────────────────────────┐
│        PowerSync Service        │
└────────────────┬────────────────┘
                 │ Filtered Sync Stream (sync_rules.yaml)
                 ▼
┌─────────────────────────────────┐
│    Local SQLite WASM Engine     │
│   (Inside Field Agent Phone)    │
└────────────────┬────────────────┘
                 │ 0ms Local Reads / Offline Writes
                 ▼
┌─────────────────────────────────┐
│     Field Agent PWA (/kiosk)    │
└─────────────────────────────────┘
```

## 2. PowerSync Tenant Sync Rules (`sync_rules.yaml`)

Sync rules guarantee that field agents only download data belonging to their specific organization and their permitted roles:

```yaml
# sync_rules.yaml for Contour
bucket_definitions:
  user_organization_data:
    parameters:
      - select organization_id from user_memberships where user_id = request.user_id()
    data:
      # Sync properties belonging to agent's organization
      - select * from properties where organization_id = bucket.organization_id
      
      # Sync active deals assigned to agent or owned by organization
      - select * from deals where organization_id = bucket.organization_id
      
      # Sync clients protected by agent or shared in org
      - select * from clients where organization_id = bucket.organization_id

      # Masked landlord view: Exclude private bank account columns
      - select id, organization_id, title, price, currency, bedrooms, bathrooms, 
               latitude, longitude, landmark_directions, status 
        from properties 
        where organization_id = bucket.organization_id
```

## 3. Conflict Resolution & Idempotent Sync

When an agent logs a client lead or notes while offline:
- The mutation is assigned a client-side UUID and timestamp.
- Upon reconnection, PowerSync transmits the batch to `/api/sync/mutations`.
- The server applies mutations idempotently using transaction-scoped `MutationReceipt` records, ensuring zero duplicate entries or overwritten data.
